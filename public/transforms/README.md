# Landmark transforms

Generated by [`scripts/gen-transforms.py`](../../scripts/gen-transforms.py). **Do not edit by
hand** — re-run the script instead. It also writes
[`src/data/transforms/manifest.json`](../../src/data/transforms/manifest.json), which is the
half Coda imports statically, and the two have to be produced in the same run:
`landmarks.ts` refuses a file whose row count disagrees with the manifest.

```
python3 scripts/gen-transforms.py
```

Needs `navis`, `flybrains` and the Saalfeld H5 registrations
(`flybrains.download_jrc_transforms()`; check with `flybrains.report()`). About 25 seconds for
the whole set.

## Why these are served rather than bundled

They are 20–200 kB each and a session touches at most two of them, so bundling would put every
dataset's landmarks in every visitor's download. And a fetched URL is the same mechanism a
user-supplied transform will use, which makes custom transforms a URL field rather than a second
loading path.

## What is in each file

`<SPACE>_mirror.csv` — `x_flip,y_flip,z_flip` → `x_mirr,y_mirr,z_mirr`, both in nanometres.
Copied from navis-flybrains, which registers a **direct** mirror landmark set for each of these
spaces. The source side is *already affine-flipped*: Coda applies `x' = flipAt - x` itself (the
constant is in the manifest, read off the template's bounding box) and the spline corrects only
the left/right asymmetry that is left. That split is navis's, and it is what the files were
fitted against — a different flip constant hands the spline a pre-image it has never seen.

`<SPACE>_JRC2018U.csv` — `x,y,z` (nm) → `jrc2018u_x,jrc2018u_y,jrc2018u_z` (**µm**; Coda
converts on load). Generated here by sampling inside the space's own shell mesh, padded 10 µm,
and pushing every sample through the full navis route. One direct edge per dataset to the common
template; there is no bridging graph in the browser.

Accuracy of the shortcut against the full navis route, 3,000 independent shell vertices each:

| space | median | p95 | max |
| --- | --- | --- | --- |
| `JRCFIB2018F` | 0.77 µm | 2.31 | 7.15 |
| `FLYWIRE` | 0.87 | 2.49 | 5.42 |
| `MANC` | 0.54 | 1.81 | 4.33 |
| `JRCFIB2022M` | 0.61 | 4.42 | 167.34 |

**MaleCNS's tail is the neck**, and it is structural rather than a sampling artefact: 64 of
3,000 points exceed 10 µm, all at the brain/nerve-cord boundary, where the two halves reach the
common frame by different routes and one spline has to interpolate across their disagreement.
Nearest-landmark distance is no worse there than elsewhere. A combined `JRC2018Ucns` space will
remove it; splitting into two landmark sets would not, since it would cut a descending neuron in
half instead.

## Provenance

The mirror files are copies of navis-flybrains' own, named in each manifest entry's `origin`.
The JRC2018U sets are derived from the Saalfeld lab's registrations via navis. The
`JRCVNC2018U → JRC2018U` affine that places a nerve cord beside a brain is lifted verbatim from
navis-flybrains' `maleCNS_JRC2018U_landmarks.ipynb`, so the two agree; **it is a layout, not a
registration**, and a VNC coordinate in JRC2018U means nothing anatomical.
