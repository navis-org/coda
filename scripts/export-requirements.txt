# The libraries the generated notebooks import. They are installed in CI so
# `check-export.py --strict` can resolve attribute chains against the real packages.
#
# Nothing that would reach a *service* is ever executed — no token, no network beyond the
# install. `probe-py-helpers.py` does run the generated pandas helpers, against a stub
# client, which is why pandas is listed rather than merely arriving with navis.
#
# This file exists to be a file: `actions/setup-python`'s pip cache is keyed on a
# dependency manifest and fails outright when it can find none. Naming it here also
# keeps the versions the checker resolved against in the repository rather than in a
# workflow step.
# The generated notebooks import these packages at runtime, and the strict checker resolves
# those module names against the environment. Keeping the full set here is what makes CI's
# `scripts/check-export.py --strict` meaningful instead of a false positive on a half-installed stack.
neuprint-python
git+https://github.com/navis-org/navis@master
# Fly templates published for the export fixtures.
flybrains
# The scientific stack used by the generated notebooks.
matplotlib
networkx
numpy
pandas
scipy
seaborn
navis-fastcore

# explicitly because `probe-py-helpers.py` *runs* the generated helpers rather than only
# resolving their names — the one check here that executes anything.
caveclient
